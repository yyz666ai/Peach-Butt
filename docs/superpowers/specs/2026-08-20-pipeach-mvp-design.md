# 桃屁屁桌宠 MVP 设计规格

日期：2026-08-20  
目标平台：macOS 首测，Windows 共用代码与打包配置  
技术方案：Electron + React + TypeScript

## 1. 产品目标

桃屁屁是一款面向程序员和久坐办公人群的健康陪伴桌宠。它以透明、无边框、始终置顶的小窗口常驻桌面，通过番茄钟、喝水、上厕所、起身和眼睛休息提醒，帮助用户减少连续久坐。

首版必须形成完整闭环：持续使用电脑导致压力上升；用户主动点击桃屁屁休息或响应提醒后减压；长期忽略会触发气球膨胀与爆炸并扣除当日健康分；所有行为在本地统计页中可回顾。

## 2. 不可违反的视觉约束

- 桃屁屁角色图、动作图、状态图和装饰性角色插画必须使用用户提供的参考图作为图生图输入生成。
- 不允许用 HTML、CSS、SVG、Canvas 几何图形或通用占位图拼造、重画或代替桃屁屁角色。
- HTML/CSS 仅用于按钮、文字、卡片、气泡、布局和数据图表等界面结构。
- 角色必须保持参考图中的关键特征：桃形兼气球形身体、顶部气球嘴、两片草地绿叶子、粉桃渐变、黑色细线四肢、软质 3D 玩具质感。
- 2026-08-20 后续新增动作严格保持原始参考图的身体比例与腿长，除动作和表情外不修改角色比例；已生成资产不返工。
- 新生成角色资产优先要求透明背景；若图生图输出白底，则经过主体分割生成真正带 alpha 的 PNG，并检查边缘闪烁和白边。
- 已有视频只作为动作节奏和姿态参考，不直接截帧作为最终角色图；不能把视频中的白色背景或角色漂移带入桌宠窗口。

## 3. MVP 范围

### 3.1 桌宠窗口

- 透明、无边框、置顶、不进入 Dock/任务栏主窗口列表。
- 支持鼠标点击、拖拽、右键菜单和非角色区域点击穿透。
- 记忆桌宠位置；多显示器切换后自动修正到可见区域。
- 默认显示角色和简短状态，不永久显示大型面板。
- 提醒气泡提供“完成”“我要休息”“5 分钟后”操作。

### 3.2 番茄钟

- 默认 25 分钟专注、5 分钟休息，可配置。
- 支持开始、暂停、继续、跳过和重置。
- macOS 菜单栏显示剩余时间；Windows 使用托盘 tooltip 与菜单显示。
- 番茄结束后，桃屁屁播放提醒动作并等待用户点击。
- 点击角色确认休息后播放开心反馈、降低压力、进入休息状态并记录事件。

### 3.3 健康提醒

- 起身：默认连续活跃 50 分钟。
- 喝水：默认 60 分钟。
- 上厕所：默认 150 分钟。
- 眼睛休息：默认 20 分钟，提醒远眺 20 秒。
- 用户可以单独启停并调整间隔。
- 番茄专注时，非紧急提醒延后到专注结束，避免叠加打扰。

### 3.4 活跃与休息判定

- 不检测真实坐姿；用系统键鼠空闲时间作为久坐代理。
- 持续有键鼠活动且没有完成休息时，累积连续活跃时长。
- 用户点击“我要休息”后立即进入休息态并暂停久坐加压。
- 系统空闲达到 3 分钟，计为一次有效休息；提前返回记录为短休息，奖励较少。
- 不记录具体应用名称、键盘内容、鼠标位置历史或屏幕画面。

### 3.5 压力、爆炸和健康分

- 压力范围 0–100，仅在用户活跃时随时间上升。
- 番茄专注期间压力上升速度可提高，但不得因系统空闲继续加压。
- 完成提醒或有效休息降低压力；点击泄压有冷却，避免刷分。
- 压力视觉阶段：正常、微鼓、鼓胀、濒爆、爆炸后瘪掉。
- 压力达到 100 时播放爆炸动画、压力归零并扣除当日健康分。
- 当日连续爆炸扣分为 15、30、50；健康分最低为 0，不死亡。
- 每日健康分从 100 开始；健康行为用于恢复少量分数，但每日恢复有上限。

### 3.6 本地统计页

- 今日健康分、当前压力、连续活跃时间、今日活跃时间。
- 番茄次数和专注分钟数。
- 喝水、上厕所、起身、眼睛休息、主动休息次数。
- 爆炸次数、忽略提醒次数、当日最低健康分。
- 最近 7 天健康分趋势和每日行为柱状对比。
- 最近事件列表，说明每次加分、减分和减压原因。

## 4. 素材使用方案

现有 5 段视频分别提供招手、厕所提醒、电脑久坐、睡觉和膨胀/濒爆的动作参考。它们都是 H.264 白底视频，没有 alpha 通道，而且部分镜头中的角色造型会漂移。MVP 不直接截取这些视频帧作为角色资产，而是提炼关键姿态和节奏，再用用户参考图走 image2 图生图生成统一角色关键帧。

首版图生图资产至少包括：透明待机正面、点击开心、招手、喝水、起身拉伸、上厕所、睡觉、眼睛休息、三档膨胀、爆炸瞬间、爆炸后瘪掉。所有生成调用都带入同一张用户参考图；每张资产通过人工/自动检查后才进入应用。

若单张图不足以形成自然动画，优先采用轻微缩放、位移、旋转、眨眼层或粒子效果驱动，但角色本体始终来自图生图资产，不用代码重画。

## 5. 软件架构

- Electron 主进程：窗口、托盘、通知、计时、空闲检测、持久化和跨平台适配。
- Preload 桥：只暴露白名单 IPC，渲染进程不直接访问 Node。
- Pet Renderer：透明宠物窗口、角色资产播放、点击/拖拽/气泡交互。
- Dashboard Renderer：设置、统计卡片、图表和事件历史。
- Core：纯 TypeScript 状态机，包含番茄、提醒、压力、健康分与每日聚合。
- Storage：本地 SQLite；事件写入后更新当天聚合，应用重启后可恢复计时状态。

## 6. 错误处理与可靠性

- 所有计时基于时间戳差值，不依赖渲染帧率。
- 应用休眠或合盖后恢复时重新计算空闲与计时，不补算离线压力。
- 素材缺失时回退到已批准的参考图资产，不显示代码绘制角色。
- 数据库写入失败时保留内存队列并提示，不让桌宠进程崩溃。
- 通知权限被拒绝时仍保留桌宠气泡和托盘提醒。

## 7. 测试与验收

- 核心状态机使用单元测试覆盖时间推进、提醒延后、有效休息、爆炸递增扣分和跨日重置。
- Electron 集成测试覆盖创建透明窗口、托盘菜单、IPC 白名单和数据恢复。
- macOS 实机验收：置顶、跨空间、拖拽、点击穿透、菜单栏倒计时、系统空闲检测和通知。
- 素材验收：透明区域真实 alpha、角色无白底/白边、画面不闪烁、角色形象与参考图一致。
- 性能目标：待机 CPU 平均不高于 2%，内存以 200MB 为硬上限并记录实测值；动画窗口隐藏时降频。
- Windows 交付打包配置和验证清单；首轮实际运行测试在当前 Mac 完成。

## 8. 明确不做

- 首版不接入大模型对话。
- 首版不接入 Steamworks、云同步、账号、皮肤商店或付费系统。
- 首版不记录各应用的使用时长。
- 首版不声称检测真实坐姿或医疗健康状况。
