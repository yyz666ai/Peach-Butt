# 桃屁屁视觉一致性与后台统计重整设计

## 目标

修复桌宠状态切换后消失、默认显示过小、视频角色比例不一致和脚部裁切问题；复用现有源视频重新抠图，不生成新动画。同时简化后台统计界面，使用现有抽象桃屁屁 Logo，并把每日四项健康行为的完成情况与爆炸次数表达清楚。

## 已确认根因

1. `.pet-stage > *` 使用 `max-width: min(44vw, 640px)`。桌宠窗口默认只有 160px 宽，实际媒体宽度因此被限制到约 70px。
2. `.pet-stage.is-whirling .pet-media` 使用 `animation-fill-mode: both`，动画末帧为 `opacity: 0`；`is-whirling` 类没有在动画结束后移除，导致状态切换后宠物永久透明。
3. 原始 MP4 都保留在 `assets/video/source/`。实际播放的是 `assets/video/generated/` 中统一到 480×500 的透明 WebM，部分生成文件在抠图和重排画布时留下白色底边、阴影横线或脚部安全边距不足。
4. 后台右下角固定播放 `pet-v7.webm` 并强制循环，因此一直显示摸头；它同时被限制在 80–130px，视觉存在感不足。
5. 菜单栏图标仍使用角色待机 PNG，没有使用已经确定的抽象桃屁屁 Logo。

## 设计决策

### 桌宠媒体舞台

- 默认宠物尺寸改为 180px，用户旧的 140/170px 设置自动迁移为 180px。
- 桌宠窗口内媒体使用舞台可用宽高的 100%，不再使用基于窗口 `vw/vh` 的全屏限制。
- 全屏接管、奖励层和后台角色分别拥有自己的尺寸变量，避免一条全局规则同时影响小窗与全屏。
- 状态切换使用“短暂淡出后立即恢复”的动画，动画末帧必须为可见；视频加载期间保留上一状态或静态兜底。

### 视频资产

- `assets/video/source/` 是唯一源视频目录；不覆盖原 MP4。
- `assets/video/generated/` 继续存放透明 VP9 WebM。
- 所有实际状态建立明确映射，逐条抽取起始、中间、结束帧检查：主体可见、双脚/椅脚完整、底边没有白色横线、角色主体大小在统一容差内。
- 对不合格文件只重新执行抠图、边缘清理和 480×500 画布重排，不调用生成模型。

### 后台陪伴动画

- 删除摸头循环，改用现有 `happy-v7` 卖萌动画。
- 后台打开时完整播放一次，结束后停在自然稳定帧；悬停或点击可重新播放一次。
- 角色区域扩大，同时不遮挡统计卡片。

### 后台统计

- 删除“桃屁屁身体状态”卡片。
- 新卡片显示“今日爆炸 N 次”和简短的休息提醒；零次时使用正向文案，有爆炸时使用明确但不羞辱用户的提醒。
- 七日趋势以每日四项健康行为为核心：喝水、活动、护眼、上厕所都至少完成一次，才记为“今日四项完成”。
- 习惯卡片移除刺眼红色计数点，改用右上角柔和数字和完成勾选状态。
- 色彩收敛为珊瑚桃、奶油白、草叶绿和深棕文字，降低黄橙蒙层。

### 图标

- Dock、Windows 应用图标继续使用 `pipeach.icns` / `pipeach.ico`。
- macOS 菜单栏与托盘图标从 `pipeach-icon-master.png` 派生小尺寸抽象桃屁屁标记，不再使用完整角色图。

## 验收标准

- 任意状态切换后 1 秒，宠物仍可见。
- 默认桌宠主体不小于窗口宽度的 72%，不同常用状态主体高度差控制在合理范围。
- 所有实际视频的首/中/尾帧都通过脚底、边缘和可见性检查。
- 后台卖萌动画只播放一次，用户主动交互才重播。
- 后台不再出现身体状态卡；显示今日爆炸次数和七日四项完成情况。
- macOS 菜单栏显示抽象 Logo。
- macOS 完整构建与状态截图验收通过；Windows 图标与布局配置通过静态和构建检查。
