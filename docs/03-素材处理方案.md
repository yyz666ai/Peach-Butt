# 桃屁屁 · 素材处理方案（即梦视频 → 透明背景动画）

> 回答你的问题：**「是不是要弄成透明背景 + GIF」——是的，必须透明背景；但建议不要用 GIF，用 PNG 序列 / APNG / WebP。**
> 每个交互动作 = 一段「透明背景的循环（或单次播放）动画」，来自视频抽帧 + 抠图，不需要 3D 建模。

---

## 1. 现状与结论

| 现状 | 说明 |
|---|---|
| 参考图 | `桃屁屁_绿色方案3_草地绿.png`，3168×1344，**RGB 无 alpha 透明通道**（所以需要抠图） |
| 动作素材 | 即梦生成的视频（MP4），含背景 |
| 结论 | 可以纯视频，不用建模。管线 = **抽帧 → 抠背景 → 透明序列 → 打包动画** |

**动画格式最终建议：**

| 用途 | 建议格式 | 理由 |
|---|---|---|
| 引擎播放 | **PNG 序列 / 精灵表** | 帧率、循环、混合全可控，边缘质量最好 |
| 单文件分发/预览 | **APNG 或 WebP** | 真彩 + 半透明，体积比 GIF 小 |
| 兜底/兼容 | GIF | 仅当对方只能读 GIF 时用（256 色会 banding）|

---

## 2. 管线总览

```
① 即梦视频（MP4，尽量绿幕/纯色背景）
      ↓ ffmpeg 抽帧
② PNG 序列（15~20fps）
      ↓ 抠背景（二选一或叠加）
③ RGBA 透明 PNG 序列
      ↓ 尺寸规范化 + 打包
④ 精灵表 / APNG / WebP + manifest.json
      ↓
⑤ 引擎（PixiJS 等）按动作播放
```

---

## 3. 第 1 步：抽帧（ffmpeg）

```bash
# 每段视频一个动作，输出到独立目录
ffmpeg -i 动作_喝水.mp4 -vf "fps=15,scale=512:-1" -q:v 2 frames_喝水/%04d.png
```

- `fps=15`：15 帧/秒足够平滑，体积小（视频若 30fps 会抽掉一半）。
- `scale=512:-1`：统一宽度（如 512），高度自适应；后续统一到方形画布。
- 抽帧后检查首尾是否有「水印/黑边/转场」，剪掉不干净的帧。

---

## 4. 第 2 步：抠背景

### 路线 A：绿幕/纯色背景（推荐，最快最干净）

**关键：让即梦生成时就用纯色背景**，提示词里加：
> 「纯色纯绿背景，chroma key 绿幕背景，画面中只有角色，无其他物体，无文字，无水印，平视，全身」

生成后用 ffmpeg 一键抠绿：

```bash
# 抠绿（颜色 0x00FF00，可调容忍度与羽化）
ffmpeg -i frames_喝水/%04d.png -vf "chromakey=0x00FF00:0.15:0.15" -pix_fmt rgba out_喝水/%04d.png

# 若边缘发绿，用 colorkey 或调高羽化：
# ffmpeg -i frames_喝水/%04d.png -vf "colorkey=0x00FF00:0.25:0.1" -pix_fmt rgba out_喝水/%04d.png
```

- `chromakey=颜色:相似度:混合度`，相似度调大抠更多、调小保留更多；混合度控制边缘羽化。
- 纯绿最适合；品红（magenta）也行，但角色是粉色/红系，**别用品红**，会误抠身体。**用绿/蓝**。

### 路线 B：AI 分割抠图（任意背景）

任意背景（非绿幕）视频用 AI 逐帧抠图：

```bash
# 安装（建议 onnxruntime 版，轻量，不用装完整 PyTorch）
pip install rembg[cpu] pillow

# 单张抠图
rembg i input.png output.png

# 批量（脚本）
for f in frames_喝水/*.png; do rembg i "$f" "out_喝水/$(basename $f)"; done
```

- `rembg` 用 U²-Net 分割人/主体，对卡通角色效果通常不错，但**逐帧边缘可能闪烁**。
- 后处理：边缘羽化、时间维平滑（相邻帧蒙版平均）可减闪烁，见 5.3。

**推荐组合**：即梦尽量绿幕 → 用路线 A 为主 → 边缘不理想处用 rembg 补一张重新生成该帧。

## 5. 第 3 步：打包成动画

### 5.1 转 APNG（单文件、真彩、半透明）

```bash
ffmpeg -framerate 15 -i out_喝水/%04d.png -plays 0 -f apng 喝水.apng
```

### 5.2 转 WebP 动图（体积最小）

```bash
ffmpeg -framerate 15 -i out_喝水/%04d.png -loop 0 -lossless 0 -q:v 90 喝水.webp
```

### 5.3 转 GIF（仅兜底）

```bash
# 生成调色板提高 GIF 质量
ffmpeg -framerate 15 -i out_喝水/%04d.png -vf "split[s0][s1];[s0]palettegen=reserve_transparent=1:transparency_color=ffffff[p];[s1][p]paletteuse" -loop 0 喝水.gif
```

### 5.4 拼精灵表（引擎推荐）

用 TexturePacker（商业）或免费工具：
- `spritesheet-js`（npm）
- ImageMagick `montage`：
  ```bash
  montage out_喝水/*.png -tile 8x -geometry +0+0 -background none 喝水_sheet.png
  ```
- 或 ffmpeg `tile` 滤镜：
  ```bash
  ffmpeg -framerate 15 -i out_喝水/%04d.png -vf "tile=8x4" -frames:v 1 喝水_sheet.png
  ```

## 6. 尺寸 / 帧率 / 质量规范（统一，避免动作间大小跳变）

| 项 | 建议值 |
|---|---|
| 画布 | 统一 512×512 或 1024×1024，角色居中，四周留 10~15% 呼吸空间 |
| 帧率 | 15~20fps（待机可 12fps）|
| 动作时长 | 循环动作 1~2s；单次触发动作 1~3s |
| 锚点 | 记录「脚底/中心」锚点，保证落地、贴边一致 |
| 命名 | `动作名_状态.png`，如 `idle_breath_00.png` |
| 清单 | 每个动作一条 manifest 记录 |

---

## 7. manifest.json（动作资产清单）

引擎按此清单加载与播放：

```json
{
  "actions": [
    {
      "id": "idle_breath",
      "name": "待机呼吸",
      "type": "loop",              // loop=循环 / once=单次播放
      "fps": 15,
      "frames": "sheets/idle_breath_sheet.png",
      "frameCount": 24,
      "anchor": { "x": 0.5, "y": 0.85 },
      "size": { "w": 512, "h": 512 },
      "trigger": "always"
    },
    {
      "id": "remind_water",
      "name": "喝水提醒",
      "type": "once",
      "fps": 15,
      "frames": "sheets/remind_water_sheet.png",
      "frameCount": 45,
      "anchor": { "x": 0.5, "y": 0.85 },
      "trigger": "scheduler:water"
    }
  ]
}
```

## 8. 角色一致性（重要：视频动作之间别「变脸」）

即梦生成多个动作时，角色容易漂移。用 **gpt-image-2 图生图**锁定角色基准，作为「角色三视图/表情集」传给即梦当参考，或直接用图生图产出关键帧：

1. 用参考图 `桃屁屁_绿色方案3_草地绿.png` 生成**角色设定集**（正面/侧面/背面 + 表情集 + 常见姿态），固定配色与特征。
2. 每个动作的提示词都粘贴**同一段「角色描述模板」**（见《04-交互设计与提示词.md》），保证一致性。
3. 即梦若支持「参考图/角色参考」功能，就传角色设定集当参考。

> 文生图/图生图 API 已在本机联调通过，可直接用（见《05-生图API联调记录.md》）。

## 10. 快速自检清单

- [ ] 视频是绿幕/纯色背景（不是，就用 rembg 路线）
- [ ] 抽帧 15fps、无黑边/水印/转场脏帧
- [ ] 抠图后边缘干净、无绿边、无闪烁
- [ ] 全部动作统一画布尺寸与锚点
- [ ] 每个动作有 manifest 记录（循环/单次、帧率、锚点）
- [ ] 角色三视图锁定了形象一致性
