# 桃屁屁动态视频资产工作流

这份文档用于把用户以后提供的固定镜头动作视频转换成桌宠可用的透明动效。目标是：可复现、主体尺寸一致、循环不抽帧、切换不跳变、最终应用不依赖 Python 模型。

## 1. 目录和命名

```text
assets/video/
├── source/       # 用户原始 MP4，保留原文件内容
├── generated/    # 应用直接使用的透明 WebM
└── manifest.json # 动作角色、时间段和循环信息
```

将新视频复制到 `source/` 后使用简短稳定的英文动作名，例如 `drink.mp4`、`stretch.mp4`。不要覆盖旧动作；同动作新版本可加 `-v2`，确认替换后再更新 manifest。

## 2. 先看片，再决定处理方式

先读取视频分辨率、帧率、时长和音轨：

```bash
ffprobe -v error -show_streams -show_format -of json assets/video/source/action.mp4
```

再生成接触表或等间隔截图，标出主动作起止、循环候选、必须保留的道具、产生跳变的尾帧，以及背景与道具是否颜色接近。不要在没看完整段视频时直接使用整段循环。

## 3. 抽帧与去背

项目脚本：`scripts/build-transparent-videos.py`。推荐在一次性 Python 虚拟环境中安装 `Pillow`、`rembg` 和 CPU 推理依赖。最终 WebM 随应用交付，普通用户无需安装这些工具。

脚本默认流程：FFmpeg 按 12fps 抽帧并缩放到 560px 宽；`rembg` 使用 `u2netp` 模型逐帧分割；保留 RGBA PNG；编码为 VP9 Alpha WebM。

```bash
npm run videos:build

# 只重做某个动作
python3 scripts/build-transparent-videos.py \
  assets/video/source assets/video/generated \
  --only focus
```

编码关键参数：

```text
-c:v libvpx-vp9
-pix_fmt yuva420p
-auto-alt-ref 0
-an
```

灰白渐变背景不适合只用 `colorkey`，否则会误删浅色电脑、马桶或椅子。优先使用分割模型；若边缘仍有灰边，再对 Alpha 做轻微收缩和羽化，而不是提高全局色键容差。

## 4. 尺寸与锚点归一

这是解决“鼠标一过去突然变小”的关键步骤。

1. 对每帧 Alpha 计算非透明包围盒。
2. 统计动作中主体包围盒的中位宽高，排除爆炸飞散帧。
3. 为普通状态设置统一目标可视高度；压力膨胀可按设计扩大。
4. 建立底部锚点：站立角色用脚底，坐姿角色用椅脚或身体最低有效接触点。
5. 将帧贴入统一透明画布，水平居中并对齐底部锚点。
6. 保留 6%–10% 安全边距，叶子、手脚和爆炸碎片不能被裁切。

验收：在相同容器内切换待机、挥手、专注、睡觉和厕所，主体视觉高度误差应小于 5%，底部不能上下跳。

## 5. 裁头、裁尾与循环

问候、厕所、变身和爆炸是单次动作：去掉动作前后的空等帧，播放结束后由状态机回到待机或主状态，不循环整段。问候必须让运行时状态覆盖完整素材时长，不能只裁好了视频又被状态机提前切走。变身若关键结果（例如旋风）在后半段才出现，必须保留到该结果，优先适度提高播放速度而不是提前裁断。

专注和睡觉只循环安静段。选择首尾点时检查主体轮廓、手/叶子/眼睛/道具位置、亮度与 Alpha 差、播放速度。如果末帧与首帧割裂，向前裁掉末尾回位帧；不要用持续缩放或晃动掩盖接缝。最终连续播放 10 个循环肉眼检查。

在 `assets/video/manifest.json` 记录运行时间段：

```json
{
  "id": "focus",
  "file": "generated/focus.webm",
  "role": "专注时安静敲电脑",
  "loopStart": 0.4,
  "loopEnd": 5.8
}
```

运行时到达 `loopEnd` 后跳回 `loopStart`，不要依赖 `<video loop>` 循环整段。

## 6. 爆炸专用处理

压力视频分成两个逻辑片段：爆炸前的变红、变胀用于压力预览；全屏爆炸只保留桃子破裂与飞散的短片。

爆炸段必须在“只剩椅子”之前结束。若爆裂瞬间的椅子仍明显：

1. 从背景或相邻空帧构建椅子区域的干净底图。
2. 对椅子区域建立固定或逐帧蒙版。
3. 保留桃子碎片 Alpha，清除椅子 Alpha。
4. 重新编码短 WebM。
5. 检查最后 5 帧，禁止孤立椅子或灰色残影。

全屏播放使用透明独立窗口，显示在宠物当前所在的显示器上。结束或异常关闭都必须回到瘪气小窗。

## 7. 动作映射

| 动作类型 | 自动播放规则 | 循环 |
| --- | --- | --- |
| 启动问候 | 每次应用启动一次 | 否 |
| 悬停问候 | 首次合格悬停，随后冷却 | 否 |
| 专注 | 番茄工作阶段 | 只循环低动作段 |
| 睡觉 | 番茄休息阶段 | 只循环稳定睡眠段 |
| 厕所 | 完成厕所提醒 | 否 |
| 压力 | 压力超过阈值，按进度定位 | 否 |
| 爆炸 | 压力达到上限 | 否，只播爆开短段 |
| 变身 | 开始或取消专注 | 否，完整保留跳起、旋转和黑色小旋风；可用 1.25 倍速压缩等待 |
| 干裂 | 喝水提醒显示满 15 分钟仍未确认 | 否，停在干裂的最后一帧 |
| 喝水恢复 | 用户确认已喝水 | 否，从同一干裂素材的喝水段继续 |

待机不自动循环视频。统计页内角色同样只在首次进入或悬停时单次活动，其余时间静止。

## 7.1 提醒与动作的衔接

- 每个番茄结束：桌宠先显示起身气泡和伸展示范；用户确认后才进入休息。
- 两个完整番茄：第二段休息结束时，桌宠显示喝水气泡，并播放喝水示范段；15 分钟未确认则停在干裂段。
- 厕所、护眼等：按定时规则排队，不在专注中打断；回到可提醒状态后先展示气泡，再播放对应素材。
- 气泡由透明窗口的独立上方空间承载；绝不能缩放、遮挡或裁掉桌宠的腿、椅脚和道具。

## 8. 校验与人工验收

```bash
npm run videos:check
```

当前自动校验确认文件存在、VP9、Alpha 标记和无音轨。后续应增加：输出尺寸/帧率、manifest 时间范围、普通动作包围盒/底部锚点误差、循环首尾帧差、爆炸最后数帧的椅子区域检查。

- [ ] 透明边缘无明显白边、灰边和抖动。
- [ ] 必要道具没有被误删。
- [ ] 悬停切换不突然变大或变小。
- [ ] 专注和睡觉连续循环 10 次无明显接缝。
- [ ] 问候只播放一次并回待机。
- [ ] 爆炸只保留爆开瞬间，最后无椅子。
- [ ] 全屏爆炸结束后小窗恢复且能点击。

## 9. 新增视频标准流程

1. 备份到 `assets/video/source/` 并规范命名。
2. 用 ffprobe 和接触表审阅整段视频。
3. 标注主动作、循环候选和必须删除的尾帧。
4. 运行 rembg 去背和 Alpha 编码。
5. 统一画布、主体大小和底部锚点。
6. 裁头尾并处理循环接缝；必要时逐帧遮罩多余道具。
7. 更新 manifest 和运行时动作映射。
8. 运行自动素材校验。
9. 在透明桌面窗口中人工检查 10 次循环与状态切换。
10. 将处理参数、时间点和例外情况补回本文件或素材清单。
