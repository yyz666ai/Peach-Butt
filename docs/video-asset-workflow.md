# 桃屁屁动态视频资产工作流

这份文档用于把用户以后提供的固定镜头动作视频转换成桌宠可用的透明动效。目标是：可复现、主体尺寸一致、循环不抽帧、切换不跳变、最终应用不依赖 Python 模型。

## 1. 目录和命名

```text
assets/video/
├── source/       # 用户原始 MP4，保留原文件内容
├── generated/    # 应用直接使用的透明 WebM
└── manifest.json # 动作角色、时间段和循环信息
```

将新视频复制到 `source/` 后使用简短稳定的英文动作名，例如 `drink.mp4`、`stretch.mp4`。不要覆盖旧动作；同动作新版本可加 `-v2`，确认替换后再更新 manifest。

## 2. 先看片，再决定处理方式

先读取视频分辨率、帧率、时长和音轨：

```bash
ffprobe -v error -show_streams -show_format -of json assets/video/source/action.mp4
```

再生成接触表或等间隔截图，标出主动作起止、循环候选、必须保留的道具、产生跳变的尾帧，以及背景与道具是否颜色接近。不要在没看完整段视频时直接使用整段循环。

## 3. 抽帧与去背

项目脚本：`scripts/build-transparent-videos.py`。依赖版本固定在 `scripts/requirements-video.txt`；脚本缺少依赖时会直接给出安装命令。最终 WebM 随应用交付，普通用户无需安装这些工具。

脚本默认流程：FFmpeg 按 12fps 抽帧并缩放到 560px 宽；`rembg` 使用 `u2netp` 模型逐帧分割；保留 RGBA PNG；编码为 VP9 Alpha WebM。

```bash
python3 -m venv .venv-video
.venv-video/bin/python -m pip install -r scripts/requirements-video.txt
.venv-video/bin/python scripts/build-transparent-videos.py \
  assets/video/source assets/video/generated

# 只重做某个动作
.venv-video/bin/python scripts/build-transparent-videos.py \
  assets/video/source assets/video/generated \
  --only focus
```

编码关键参数：

```text
-c:v libvpx-vp9
-pix_fmt yuva420p
-auto-alt-ref 0
-an
```

灰白渐变背景不适合只用 `colorkey`，否则会误删浅色电脑、马桶或椅子。优先使用分割模型；若边缘仍有灰边，再对 Alpha 做轻微收缩和羽化，而不是提高全局色键容差。

## 4. 尺寸与锚点归一

这是解决“鼠标一过去突然变小”的关键步骤。

1. 对每帧 Alpha 计算非透明包围盒。
2. 统计动作中主体包围盒的中位宽高，排除爆炸飞散帧。
3. 为普通状态设置统一目标可视高度；压力膨胀可按设计扩大。
4. 建立底部锚点：站立角色用脚底，坐姿角色用椅脚或身体最低有效接触点。
5. 将帧贴入统一透明画布，水平居中并对齐底部锚点。普通动作保留 8px 底部安全区；带椅子的专注素材额外缩小并保留 18px，避免椅脚贴边。
6. 保留 6%–10% 安全边距，叶子、手脚和爆炸碎片不能被裁切。

验收：在相同容器内切换待机、挥手、专注、睡觉和厕所，主体视觉高度误差应小于 5%，底部不能上下跳。

## 5. 裁头、裁尾与循环

问候、厕所、变身和爆炸是单次动作：去掉动作前后的空等帧，播放结束后由状态机回到待机或主状态，不循环整段。问候必须让运行时状态覆盖完整素材时长，不能只裁好了视频又被状态机提前切走。变身若关键结果（例如旋风）在后半段才出现，必须保留到该结果，优先适度提高播放速度而不是提前裁断。

专注和睡觉只循环安静段。当前专注循环使用 `0.35s–3.67s`；睡觉尾部用 12 帧交叉淡化回首帧，避免气泡瞬间消失。选择首尾点时检查主体轮廓、手/叶子/眼睛/道具位置、亮度与 Alpha 差、播放速度。如果末帧与首帧割裂，向前裁掉末尾回位帧或做短交叉淡化；不要用持续缩放或晃动掩盖接缝。最终连续播放 10 个循环肉眼检查。

在 `assets/video/manifest.json` 记录运行时间段：

```json
{
  "id": "focus",
  "file": "generated/focus.webm",
  "role": "专注时安静敲电脑",
  "loopStart": 0.4,
  "loopEnd": 5.8
}
```

运行时到达 `loopEnd` 后跳回 `loopStart`，不要依赖 `<video loop>` 循环整段。

## 6. 爆炸专用处理

压力视频分成两个逻辑片段：爆炸前的变红、变胀用于压力预览；全屏爆炸只保留桃子破裂与飞散的短片。

爆炸段必须在“只剩椅子”之前结束。若爆裂瞬间的椅子仍明显：

1. 从背景或相邻空帧构建椅子区域的干净底图。
2. 对椅子区域建立固定或逐帧蒙版。
3. 保留桃子碎片 Alpha，清除椅子 Alpha。
4. 重新编码短 WebM。
5. 检查最后 5 帧，禁止孤立椅子或灰色残影。

全屏播放使用透明独立窗口，显示在宠物当前所在的显示器上。结束或异常关闭都必须回到瘪气小窗。

## 7. 动作映射

| 动作类型 | 自动播放规则 | 循环 |
| --- | --- | --- |
| 打招呼 | 只有用户明确点击“打招呼”时完整播放 | 否 |
| 专注 | 番茄工作阶段 | 只循环低动作段 |
| 睡觉 | 每 4 个番茄后的长休息 | 只循环稳定睡眠段 |
| 厕所 | 完成厕所提醒 | 否 |
| 压力 | 压力超过阈值，按进度定位 | 否 |
| 爆炸 | 压力达到上限 | 否，只播爆开短段 |
| 变身 | 开始或取消专注 | 否，完整保留至 9.82s 的跳起、旋转和旋风尾部；以 1.55 倍速播放并在末尾淡出 |
| 活动 | 当前休息四项轮播中的“活动一下” | 是，4 秒低幅度拉伸循环 |
| 待机 | 启动问候结束后的普通陪伴状态 | 是，但每 4 秒只出现一次轻微眨眼/手脚动作 |
| 眼睛干裂 | 护眼提醒显示满 10 分钟仍未确认 | 否，逐级变红、干裂并停在最后警示帧 |
| 干裂 | 喝水提醒显示满 15 分钟仍未确认 | 否，停在干裂的最后一帧 |
| 喝水恢复 | 用户确认已喝水 | 否，从同一干裂素材的喝水段继续 |

桌面待机使用 ImageGen 四帧动作表组成的 4 秒低频循环，大部分时间保持原姿，只在短暂帧中眨眼、抬手或动脚。统计页内角色仍只在首次进入或悬停时单次活动，其余时间静止。

## 7.1 当前休息四项轮播

- 每个番茄结束都创建当次队列：`stand → activity.webm`、`water → dry.webm` 的喝水段、`toilet → toilet.webm`、`eyes → eye-strain.webm`。
- 用户完成并打卡某项后，该动作立即从当次轮播移除；剩余项继续循环，不留到下一次休息。
- 第 4 个番茄的长休息轮播 `sleep.webm`。
- 气泡由透明窗口的独立上方空间承载；只显示一句短文案，不放按钮、完成/稍后或撤销操作；悬停或状态变化时出现，约 3.2 秒后自动消失。绝不能缩放、遮挡或裁掉桌宠的腿、椅脚和道具。

## 7.2 ImageGen 动作表流程

当原视频无法提供一致的待机或健康警示动作时，使用参考图生成四格横向动作表，再由 `scripts/build-generated-sprite-motion.py` 处理：

1. 四格必须共用同一角色身材、叶片、气球嘴、短腿和三指圆润手型。
2. 将动作表等分为四帧，运行 rembg `u2netp` 去掉生成图的棋盘/白底。
3. 取四帧共同主体包围盒，统一缩放到 `480 × 500` 透明画布并锁定脚底基线。
4. 对半透明边缘执行白底反算去色，并将 Alpha 向内收缩 1px；再对 RGB 轻度提亮和增色，Alpha 单独保留，避免深色桌面出现白色光圈。
5. 待机采用长停顿加短动作的帧序列；眼睛干裂采用逐级恶化并长时间停留末帧的序列。
6. 编码 VP9 Alpha WebM，并保留透明 PNG 帧和首/末帧作为回退资产。

当前输入与输出：

- `assets/generated/source/idle-motion-sheet.png` → `assets/video/generated/idle.webm`
- `assets/generated/source/eye-strain-sheet.png` → `assets/video/generated/eye-strain.webm`
- 逐帧预览：`docs/qa/idle-motion-contact-sheet.png`、`docs/qa/eye-strain-contact-sheet.png`

## 7.3 旧视频亮度与边缘修复

`scripts/build-transparent-videos.py --normalize-existing` 会对已有透明视频统一提亮、增色并重新归一画布。新的去边流程会先将 Alpha 向内收缩 1px，再按白底合成公式反算半透明边缘的 RGB，避免深色桌面上出现白轮廓。打招呼素材另外清除腿环内的白色地面残影，保留深色腿部轮廓和桃色身体。

全量色彩统一参数记录在 `BRIGHTNESS` 和 `ImageEnhance.Color(...).enhance(1.12)`；专注原片使用 1.28 亮度，其他原片使用 1.15–1.18，与静态参考图的桃粉和草地绿靠拢。

## 8. 校验与人工验收

```bash
npm run videos:check

# 生成深色和棋盘背景的逐时间线验收图
python3 scripts/build-video-contact-sheets.py
```

当前自动校验确认：文件存在、VP9 Alpha、无音轨、480×500、12fps、manifest 时间范围、休息五种映射完整，并分别抽查每段的起始/中间/结束帧。专注、压力和爆炸另查底部椅子残片；专注与睡觉另查循环首尾像素差。最终仍必须在深色与棋盘图上人工验收：

- `docs/qa/video-motion-dark-contact-sheet.png`
- `docs/qa/video-motion-checker-contact-sheet.png`

- [ ] 透明边缘无明显白边、灰边和抖动。
- [ ] 必要道具没有被误删。
- [ ] 悬停切换不突然变大或变小。
- [ ] 专注和睡觉连续循环 10 次无明显接缝。
- [ ] 问候只播放一次并回待机。
- [ ] 爆炸只保留爆开瞬间，最后无椅子。
- [ ] 全屏爆炸结束后小窗恢复且能点击。
- [ ] 气泡在鼠标不离开的情况下仍会自动消失，且始终只有一句话。
- [ ] 待机循环 10 次没有抽动、缩放或脚底跳位。
- [ ] 护眼超时动画按四级恶化并停在最终红眼干裂帧。

## 9. 新增视频标准流程

1. 备份到 `assets/video/source/` 并规范命名。
2. 用 ffprobe 和接触表审阅整段视频。
3. 标注主动作、循环候选和必须删除的尾帧。
4. 运行 rembg 去背和 Alpha 编码。
5. 统一画布、主体大小和底部锚点。
6. 裁头尾并处理循环接缝；必要时逐帧遮罩多余道具。
7. 更新 manifest 和运行时动作映射。
8. 运行自动素材校验。
9. 在透明桌面窗口中人工检查 10 次循环与状态切换。
10. 将处理参数、时间点和例外情况补回本文件或素材清单。
